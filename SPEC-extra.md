# Ak spec: extras (read only when needed)
Native target only.
## Errors, modules, CLI
Errors have a kind. The `try` handler still receives the message string; inside it `(errkind e)` is `"assert"` (`assert`; throws "assertion failed" or its message when the condition is falsy), `"arith"` (division by zero, integer overflow), `"type"` (wrong operand or argument type, not callable), `"io"` (files, `sh`, sockets), `"index"` (bad or out-of-range index) or `"error"` (`err` and the rest). `(raise "kind" "msg" data)` throws your own kind, and `(errdata e)` returns its data (nil otherwise). Both describe the error being handled, so call them first in the handler, before any code that may throw again. Uncaught errors print `error: msg (file:line:col)` (the innermost call site), then one `  called from file:line:col` per outer call (at most 10), exit 1.
`(use "f.aklang")` includes a file (two files defining one function warn, later wins). `(use "f.aklang" as g)`: its top-level names are `g.name`, so libraries never clash (top level only). `(q x)`: symbols are a type, `ty`="sym", `(sym "x")`.
`ak check f.aklang` compiles without running. `ak fmt` prints the canonical layout (drops comments). Strings across targets: see below. `ak test [paths]` runs every `*.test.aklang` under the paths (default `.`); a test is a program that exits 0; prints PASS/FAIL per file and a summary, exit 1 on any failure or when none is found. `ak repl`: an expression prints its value, a definition `x=1` / `f n = ..` / `(use ..)` is kept and replayed before each entry, so its side effects run again; `:defs` `:reset` `:q`.

## Details

with `ms`: nil if nothing arrives within `ms` milliseconds) · `(fdw fd s ms=nil)` write all (string, byte list or `u8`; with `ms`: raises `write timed out` when the peer takes nothing for `ms`) · `(fdline fd ms=nil)` one line without its `\n` or `\r\n`, nil at the end of the stream · `(fdreadn fd n ms=nil)` exactly n bytes (fewer only at the end of the stream) — both buffer what they read ahead per fd (a later `fdr` returns that first) and raise `read timed out` after `ms`, keeping what has arrived · `(fdc fd)` close · `(fdwait [fd ..] ms)` → the readable fds (ms<0: forever; an fd that is not open raises) — see `examples/httpd.aklang`. `lib/http.aklang` is an `http://` and `https://` client: `(h.get url headers opts)` `(h.post url body headers opts)` `(h.req method url body headers opts)` → `{:status :headers :body}` (a repeated header is joined with `", "`, `set-cookie` with `"\n"`; differing Content-Length values raise; Content-Length, chunked and until-close bodies, redirects; `{:h2 true}` offers HTTP/2, `https://` proxies work and `h.dial` gives other protocols the same proxy handling; `opts` is `{:roots certs :ms connect-timeout :rms read-stall-ms :wms write-stall-ms}`, stalls raise after 60 s by default). URLs follow RFC 3986: scheme in any case, `user:pass@` becomes Basic authentication, `#fragment` is dropped, `http://host?q=1` sends `/?q=1`, `[::1]` hosts parse, a bad port raises `bad port in URL`. `lib/httpd.aklang` is the server side (one task per connection on `lib/async.aklang`): `l=(s.listen port handler opts)` then `s.run()`, or `(s.serve port handler opts)`; the handler gets `{:method :path :segs :query :headers :body :version}` (`path` has `.`/`..` segments resolved and `%2F` kept as `%2F`; `segs` are the decoded segments the router matches) and returns a string, `[status type body]` or `{:status :headers :body}`; `(s.router [["GET" "/user/:id" f] ..])` builds a handler (`req.params`, 404/405); keep-alive, chunked request bodies, 400/413/431/505 for bad input (400 also for Content-Length with Transfer-Encoding and for HTTP/1.1 without exactly one Host), 500 when the handler raises or returns a bad status or a header with CR, LF or NUL; `:tls {:cert .. :key ..}` serves https (see docs/libraries.md); no HTTP/2 server. `lib/ws.aklang` is WebSocket (RFC 6455): `ws=(w.connect "ws://host/path" opts)` (or `wss://`), `(w.accept (w.fdstream fd) opts)` on the server, `(w.send ws text)` `(w.sendb ws bytes)` `(w.recv ws)` (nil once closed; `ws.bin`) `(w.ping ws)` `(w.close ws code reason)`; fragments are joined, ping answered, invalid UTF-8 in text or a close reason closes with 1007, frames over `:maxsize` (16 MB) or protocol violations close with 1009/1002. `pow`/`**` with fractional exponents may differ from V8 in the last digit; all other math functions are bit-identical to V8. Uncaught errors print `error: msg (file:line:col)` and exit 1. Memory is garbage-collected (copying GC); for stress testing set `AK_GCMIN=<bytes>` (collect after every that many bytes allocated), `AK_GCVERIFY=1` (heap verifier) and `AK_GCSTATS=1` (print the collection count at exit).
## Coroutines and tasks (native only)
A coroutine is a function with its own stack, so it can pause from any depth (inside loops, recursion, callees) and be continued later. `c=(co f)` makes one (nothing runs yet) · `(resume c v)` runs it until it `(yield x)`s (resume returns x) or finishes (resume returns its result); `v` is the argument of `f` on the first resume and what `yield` returns on later ones · `(yield x)` outside a coroutine throws · `(alive c)` false once it has finished · `(drain c)` all its yielded values in a list · `(coclose c)` throws away a coroutine that is not running (its stack is reused; nothing in it is unwound). An error that is not caught inside the coroutine ends it and is thrown again by the `resume`, with its kind and data. Resuming a finished or running coroutine throws. A coroutine can resume another one. Each has 8 MB of machine stack and 8 MB of value stack (address space only; pages are used as they are touched), so tens of thousands can be alive at once; one that is never finished and never closed keeps its stack until the program ends.
```
walk t = (? t (: walk(t[0]) (yield t[1]) walk(t[2])))      ; in-order walk of [left value right] trees
(p (drain (co ()=>walk(tree))))
```
`lib/async.aklang` builds cooperative tasks on top: `(use "lib/async.aklang" as a)` · `(a.spawn f args..)` start a task · `(a.sleep ms)` · `a.pause()` let the others run · `(a.wait fd)` until fd is readable (accept, read, end of stream) · while `a.run` works, `tcpc` `dns` `hostips` and reads with a timeout (`fdr fd n ms`, `fdline`, `udpfrom`) let the other tasks run (they poll 1-20 ms apart) · `(a.write fd s)` write all of s without blocking the other tasks (`fdw` blocks the whole process when the socket buffer is full; `(fdwp fd s off n)` writes what fits now and returns the byte count, `(fdpoll rfds wfds ms)` waits for readable and writable fds) · `a.chan()` `(a.send ch v)` `(a.recv ch)` (waits; nil once the channel is closed and empty) `(a.close ch)` · `a.run()` runs the tasks (poll(2) when all are waiting) until none is left that can progress; a task that throws prints `task error: msg` and ends. A server is then one task per connection of plain blocking-looking code (see `tests/native_only/async.aklang`: a server and 100 clients in one process). Zero-argument functions of a namespace are called `a.run()`; `(a.run)` is the function value.

## Parallel workers (native only)
`(par n f w=nil)` runs `f(0)` .. `f(n-1)` in worker processes, at most `w` at once (default `(cores)`, at most 256), and returns the list of their results in order. A worker is a copy of the whole program made with `fork`: `f` can use every variable, function and value of the parent, but what a worker changes in ordinary variables, lists and maps is not seen by the parent. Results travel back by value: nil, booleans, numbers (NaN and -0 too), strings (any bytes), lists, maps, BigInts and typed arrays; a function cannot be sent (type error). Tasks are handed out one at a time (in blocks above 1024 tasks), so uneven tasks balance themselves. If a task throws, the other workers are stopped and `par` throws the error again in the parent with its kind and data and the message `par: task 3: msg`. A worker that exits or is killed is reported (`par: a worker exited with code 7`, `par: a worker was killed by signal 9`), the rest are stopped, every worker is collected (no zombies) and a worker never outlives its parent. Output a task prints is written by its worker when the worker ends. A `par` costs about 0.7 ms plus the copying of the results: give each task at least a millisecond of work.
`(shared kind n)` is a zero-filled typed array (`kind`: `"u8" "i8" "u16" "i16" "u32" "i32" "f32" "f64"`) in memory shared with the workers: `a[i]=v` and `(<@ a i v)` in a worker are seen by the parent and the other workers, so tasks that write different elements need no locks (there are no atomics: two tasks must not write one element, and a task must not read what another writes). It lives outside the collected heap, is never moved or freed (make it once, not in a loop), and `(canvas w h true)` (`lib/canvas.aklang`) puts a canvas's pixels in one. `(cores)` is the number of CPUs the process may run on (its affinity mask), at least 1.
```
px=(shared "u8" 1000*1000)
(par 1000 y=>(for x 1000 px[y*1000+x]=x+y&255))     ; one row per task, all cores
```
`examples/mandelbrot.aklang` renders with 1 worker and with every core and reports the speed-up (3.9x on 4 cores).

## Windows and graphics (native only, Linux X11 / XWayland)

## Cryptography (native)
`(use "lib/crypto.aklang" as c)` — primitives written in Ak, for `lib/tls.aklang`; byte data is a string in and out: `c.sha1 s` (for the WebSocket handshake only) `c.sha256 s` `c.sha384 s` · `c.hmac "sha256"|"sha384" key msg` · `c.hkdf_extract hash salt ikm` `c.hkdf_expand hash prk info n` · `c.chacha_seal key nonce aad plain` / `c.chacha_open key nonce aad data` (ChaCha20-Poly1305, 12-byte nonce, tag appended) · `c.aes_gcm_seal` / `c.aes_gcm_open` (same arguments; key of 16 or 32 bytes, 12-byte nonce) · `c.x25519 scalar point` `c.x25519_base scalar` · `c.random n` (getrandom) · `c.hex s` `c.unhex h`. The `open` functions return nil when the tag does not match (an empty plain text is `""`, so test with `nil`, not truthiness). Checked against Node's crypto on random inputs (`tests/crypto.test.js`). Not constant-time (arithmetic on BigInts and lists): fine for protocols over the network, not a defence against a local attacker timing the process.

## Certificates (native)
`(use "lib/pki.aklang" as k)` — X.509 and signatures in Ak: `k.pem_certs text` → DER strings · `k.cert_parse der` → map (`subject` `issuer` `nb` `na` `key` `san` `ips` `ca` `keyusage` `sigalg` `tbs` `sig`) · `k.verify_sig key alg data sig` (RSA PKCS#1 v1.5 and PSS, ECDSA P-256/P-384, SHA-256/384; `alg` is `rsa_pkcs1_sha256`, `rsa_pss_sha384`, `ecdsa_sha256`, ..) · `k.trust_roots()` loads the system bundle (`SSL_CERT_FILE` overrides; /etc/ssl/certs/ca-certificates.crt and the usual Red Hat/Alpine paths otherwise) · `k.check_chain ders host roots now` returns the parsed leaf or raises `certificate: why`. Checked: signatures along the chain up to a root, validity dates, CA flag and keyCertSign, subjectAltName match (wildcards for one label, IPv4 addresses; the CN is ignored). Not checked: revocation, name constraints, path length, extended key usage; SHA-1 and SHA-512 signatures are rejected. A signature check takes about 30 ms (RSA-2048), 90 ms (P-256) or 220 ms (P-384).

## TLS (native)
`(use "lib/inflate.aklang" as z)` — `(z.gunzip s max)` `(z.zlib s max)` `(z.inflate s max)` decode gzip / zlib / raw deflate (checksums verified, output over max raises); `lib/http` uses it for `{:gzip true}`.

`(use "lib/tls.aklang" as t)` — a TLS 1.3 and 1.2 client and a TLS 1.3 server in Ak (the server picks the certificate by SNI with `t.creds {:names {..} :default ..}`) (needs `crypto.aklang` and `pki.aklang`, loaded by it): `cn=(t.connect host port opts)` connects (like `tcpc`, so names are resolved with DNS), handshakes, verifies the certificate chain against the system CA bundle (`opts.roots`: your own parsed CA list; `opts.ms`: connect timeout) and the host name, and raises `tls: ...` on any failure; there is no way to turn verification off. `(t.read cn n=16384)` → up to n bytes, `""` at the end (`cn.truncated` is true if the peer hung up without close_notify) · `(t.write cn s)` · `(t.close cn)` · `(t.fd cn)` for `fdwait`. Supported: x25519, TLS_AES_128_GCM_SHA256, TLS_AES_256_GCM_SHA384, TLS_CHACHA20_POLY1305_SHA256, RSA-PSS and ECDSA (P-256/P-384) server signatures, KeyUpdate. `opts.alpn` (a list of protocol names) offers ALPN and `cn.alpn` is the server's pick (nil if none); `opts.cert`/`opts.key` (PEM, as for `t.creds`) answer a server's CertificateRequest with a client certificate (without them the client sends an empty Certificate and the server decides); `cn.peer` is the verified peer certificate (parsed). TLS 1.2 (client only): ECDHE with x25519, AES-128/256-GCM or ChaCha20-Poly1305, RSA or ECDSA server certificates, extended master secret, client certificates and ALPN; TLS 1.3 is preferred when the server has it, and a downgrade marker in the ServerHello is refused. TLS 1.3 session resumption: the server sends one ticket after each full handshake (stateless: sealed with `:tkey` of `t.creds`, 32 random bytes by default, so share it between processes; valid 2 hours; none when `:clientca` is set); the client keeps them, `(t.session cn)` is the newest `{:ticket :psk :host ..}` or nil (tickets arrive after the handshake, so read first), `{:session s}` in the options of `t.connect` offers it (ignored for another host or when expired), `cn.resumed` tells whether the PSK was used and `cn.peer` is then the certificate of the original handshake. TLS 1.2 session tickets (RFC 5077): the client asks for a ticket, `(t.session cn)` returns a `{:v12 true ..}` session and `{:session s}` resumes it with the abbreviated handshake (`cn.resumed`), falling back to a full handshake when the server refuses. 0-RTT early data (TLS 1.3): `:early n` in `t.creds` (the most bytes accepted; 0 = off) makes the server announce it in its tickets and accept it on a resumed connection (it is delivered by `t.read` first and `cn.early` is true); each ticket is accepted for 0-RTT once only (a replay is answered as an ordinary connection, the data is skipped) and its age must be within 11 s of the real one, and a HelloRetryRequest refuses it; the client sends `opts.early` (a string) as 0-RTT when the session allows it and as ordinary data right after the handshake otherwise, so it is always delivered, but possibly twice at the server if a network replays the first flight: send only requests that are safe to repeat. Not supported: TLS 1.1 and older, a TLS 1.2 server side, RSA key exchange, CBC suites, TLS 1.2 session ids. Key exchange groups: x25519, secp256r1 and secp384r1 (client and server; x25519 is offered first, and a HelloRetryRequest is followed on the client and sent by the server when the key share it got is for a group it cannot use). Server side: `cr=(t.creds {:cert chain_pem :key key_pem})` loads a certificate chain (leaf first) and its unencrypted private key (PKCS#8, SEC1 or PKCS#1 PEM; RSA or EC P-256/P-384; the key must match the leaf) once; `cn=(t.accept fd cr)` does the handshake on a socket from `tcpa` and returns the same connection object as `connect` plus `cn.sni` (on failure it closes `fd` and raises `tls: ...`). Signs with RSA-PSS or ECDSA, whichever the client offered; `creds` also takes `:alpn` (the server's preference list; no overlap with a client that offered ALPN is refused), `:clientca` (PEM of trusted CAs: the client must present a certificate chaining to one, `cn.peer` is its parsed leaf) and `:optional true` (a client may send none, `cn.peer` is then nil). A handshake with an RSA key takes about 0.4 s. `lib/pki.aklang` gained `k.priv_parse pem` `k.sign key alg data` `k.key_matches priv pub`. Tested against curl and `openssl s_client` (`tests/tls_server.test.aklang`). A handshake takes about 0.2 s. Tested against Node's TLS server (all suites, EC and RSA certificates, 70 KB transfers) and OpenSSL s_server (KeyUpdate); not yet against public servers.

## Strings across targets
A native string is UTF-8 bytes; a JS string is UTF-16 units. For ASCII text the two are identical. The contract for other text:
- Same on both: `==` `++` `+` `split`/`join`/`starts`/`ends`/`has`/`rep` with a non-empty separator, `trim`, `rpt`, `show`, `json`/`unjson` (including `\u` escapes and surrogate pairs), `chr` and `ord` (code points; `ord` of a string reads its first character), regex with a literal pattern, and `idx` of a character that comes before any non-ASCII text.
- Counts units, so differs: `#s`, `s[i]`, `s[a..b]`, `take` `drop` `fst` `lst`, `for` over a string, `split s ""`, `idx` after non-ASCII text, `padl` `padr` and `fmt` widths. `(#"é")` is 2 natively and 1 on JS, `(#"😀")` is 4 and 2. A native slice may cut inside a character and give invalid UTF-8.
- Regex: `.` and classes match one code point natively; on JS only with the `u` flag: `(match (re "^.$" "u") s)`.
- `up` and `lo` map ASCII, Latin-1, Latin Extended-A, Greek and Cyrillic letters one to one natively; JS also applies special casing (`ß` -> `SS`, a final sigma), which natively stays as it is.
- File errors say why: `cannot read /x: no such file or directory` (also `permission denied`, `is a directory`, `not a directory`, `file exists`, `no space left on device`, `read-only file system`, others as `errno N`); `(mkdir "")` raises; `(sleep ms)` raises a `type` error for NaN, negative, infinite or above 2^40 ms and resumes after a signal; `ak build/exe/compile` refuse an output that is the source file itself or ends in `.aklang` or `.ak`; a repeated parameter or pattern name is a compile error (`duplicate parameter a`, `_` may repeat); a function of your own named `req`, `js`, `new` or `aw` shadows the JS interop names.
- `sh` raises an io error when the command exits non-zero (`sh failed (3): cmd`) or is killed by a signal (`sh killed by signal 9: cmd`). Regex matching is a backtracking matcher: a pattern that backtracks past a step budget (2 million plus 64 per byte of input) raises `regex too complex` instead of hanging, so untrusted input should still be matched with simple patterns.
- `(rm p)` removes a file, a symlink (never its target) or a directory with everything inside it; a missing path is not an error. Stdout write failures (full disk) raise `write failed` and exit 1.
- Sizes: a count or length above 2^31 (lists and ranges: 2^27, `json` indent: 100) raises `invalid length: n` (`rpt`, `padl`, `padr`, `a..b step`, `json`, `fdr`, `udpfrom`) instead of hanging; `(exit x)` takes nil or an integer.
Portable code treats text as opaque (compare, join, split on ASCII separators) and uses `ord`/`chr` for characters. `tests/strings.test.js` runs one table of cases on both targets, so a change in either direction fails until this section is updated.

## Destructuring a non-list (native)
`[a b]=v`, parameter patterns, `for [k v]`, `let` and nested patterns need a list or nil: any other value (`5`, `"hi"`, a map) raises `expected list, got num`. nil gives nils; a short list gives nil for the missing names (`[a b]=[1]` -> `1 nil`). The JS target still accepts anything.

## Stack overflow and cyclic data (native)
- Unbounded recursion raises `error: stack overflow` (kind `error`, catchable with `try`, with the usual location and `called from` lines) instead of a segmentation fault. The check is at every function entry and covers both the machine stack and the value stack, also inside a coroutine (8 MB each).
- `show`, `p`, `$`, `json` and `==` on a list or map that contains itself raise `cyclic structure or nesting deeper than 10000` (kind `error`).

## BigInt, `fmt` and `json` rules (native)
- `(ty 10n)` is `"big"`. `abs min max sum int flr cel` and `fmt "%d"` accept BigInts; `sqrt rpt` and the other number builtins raise `expected number, got big`. A BigInt and a number never mix in `+ - *` (`cannot add big and num`), but they compare and sort.
- `fmt` takes `%s %d %f %e %E %g %G %x %X %o %b %c %%` with `-`, `0`, `+` and space flags, a width and a precision; `%e` and `%g` round half to even like C printf (`Infinity` and `NaN` print as `fmtnum` does), `%c` takes a code point.
- `fmt` raises (kind `error`) when it runs out of arguments (`fmt: missing argument for %s`), has arguments left over (`fmt: too many arguments`), ends inside a specifier (`fmt: incomplete format`) or meets an unknown one (`fmt: unknown specifier %k`).
- `json` and `unjson` reject strings that are not valid UTF-8 (`json: string is not valid UTF-8`, `invalid JSON: string is not valid UTF-8 at position n`); encode binary data as hex or base64 first.
- `json` raises an `arith` error for `NaN`, `Infinity` and `-Infinity` (`json: cannot write NaN`) instead of writing `null`.
