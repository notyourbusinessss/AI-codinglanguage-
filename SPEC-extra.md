# Ak spec: extras (read only when needed)
Native target only.
## Errors, modules, CLI
Errors have a kind. The `try` handler still receives the message string; inside it `(errkind e)` is `"assert"` (`assert`; throws "assertion failed" or its message when the condition is falsy), `"arith"` (division by zero, integer overflow), `"type"` (wrong operand or argument type, not callable), `"io"` (files, `sh`, sockets), `"index"` (bad or out-of-range index) or `"error"` (`err` and the rest). `(raise "kind" "msg" data)` throws your own kind, and `(errdata e)` returns its data (nil otherwise). Both describe the error being handled, so call them first in the handler, before any code that may throw again. Uncaught errors print `error: msg (file:line:col)` (the innermost call site), then one `  called from file:line:col` per outer call (at most 10), exit 1.
`(use "f.aklang")` includes a file (two files defining one function warn, later wins). `(use "f.aklang" as g)`: its top-level names are `g.name`, so libraries never clash (top level only). `(q x)`: symbols are a type, `ty`="sym", `(sym "x")`.
`ak check f.aklang` compiles without running. `ak fmt` prints the canonical layout (drops comments). Strings across targets: see below. `ak test [paths]` runs every `*.test.aklang` under the paths (default `.`); a test is a program that exits 0; prints PASS/FAIL per file and a summary, exit 1 on any failure or when none is found. `ak repl`: an expression prints its value, a definition `x=1` / `f n = ..` / `(use ..)` is kept and replayed before each entry, so its side effects run again; `:defs` `:reset` `:q`.
## Less common builtins and details (kept out of SPEC.md to save tokens)
math `+ - * / % // ** < > <= >= == != !` `& | ^ << >> >>> bnot` (bit operators work on 32-bit integers like JS: `2**40|0` is 0, `>>>` is unsigned) `sin cos tan asin acos atan atan2 exp log log2 log10 pow cbrt hypot sinh cosh tanh sign` (precedence, tight to loose: `**` · unary · `* / // %` · `+ -` · `<< >>` · `&` · `^` · `|` · `..` · `< > <= >= == !=` · `&&` · `|| ??` · `= += -= *= /= %= **= //= ||= ??=` · `=>`; several-statement lambda: `(\ (x) s1 s2 result)`)
typed arrays `f64 f32 i32 u32 i16 u16 i8 u8 bcat` (`(u8 n)`, `(bcat a b ..)` joins byte lists/arrays into one `u8`) · fast unchecked access `(@! a i)` `(<@! a i v)`
io `wrx runx selfexe isatty delay raise errkind errdata sym mksym symline symcol bytes f64bits ev imp` (`wr` `app` `wrx` take a string or byte list; `wrx` = executable; `(sym "x")`, `ty` of a symbol is "sym")
Forms: `(let (x 1 y 2) body..)` · `(use "f.aklang" as g)` its names become `g.name` · `(q x)` quote · `(raise kind "msg" data)` `(errkind e)` `(errdata e)` · `ak -e 'code' [args]` · `ak build f.aklang out` native executable · `ak check f.aklang`.
Semantics: bools count as 0/1 in arithmetic; `+` concatenates str+any; loop variables are per-iteration; `for` fixes the list length at loop start; recursion depth is large (512MB stack); maps sort as `[k v]` entries; `m.k=v` sets a key; `ak --fast` (JS target) skips the integer overflow checks.
## Details
Native only (sockets, IPv4 TCP, blocking; on the JS target each of these raises `name: sockets are native only`): `(tcpl port host="0.0.0.0")` listen → fd (port 0 = pick one) · `(tcpp fd)` local port · `(tcpa fd)` accept → fd · `(tcpc host port ms=nil)` connect → fd (host: dotted IPv4, `localhost`, a name in /etc/hosts, or any name the nameservers in /etc/resolv.conf resolve; every address of the name is tried in turn; `ms` = connect timeout per address; TLS: see `lib/tls.aklang` below) · `(dns name)` → its IPv4 addresses as dotted strings (raises `cannot resolve name`; `AK_DNS=ip[:port]` overrides the nameserver; A records over UDP, 2 s timeout, 2 rounds, no cache, no IPv6/TCP fallback) · `(udp)` UDP socket fd · `(udpto fd ip port s)` send a datagram · `(udpfrom fd n=65536 ms=nil)` receive one (nil after `ms`) · `(fdr fd n=65536)` read ≤n bytes (`""` = end of stream) · `(fdw fd s)` write all (string, byte list or `u8`) · `(fdc fd)` close · `(fdwait [fd ..] ms)` → the readable fds (ms<0: forever) — see `examples/httpd.aklang`. `lib/http.aklang` is an `http://` and `https://` client: `(h.get url headers opts)` `(h.post url body headers opts)` `(h.req method url body headers opts)` → `{:status :headers :body}` (Content-Length, chunked and until-close bodies, redirects; `opts` is `{:roots certs :ms connect-timeout}`). `pow`/`**` with fractional exponents may differ from V8 in the last digit; all other math functions are bit-identical to V8. Uncaught errors print `error: msg (file:line:col)` and exit 1. Memory is garbage-collected (copying GC); for stress testing set `AK_GCMIN=<bytes>` (collect after every that many bytes allocated), `AK_GCVERIFY=1` (heap verifier) and `AK_GCSTATS=1` (print the collection count at exit).
## Coroutines and tasks (native only)
A coroutine is a function with its own stack, so it can pause from any depth (inside loops, recursion, callees) and be continued later. `c=(co f)` makes one (nothing runs yet) · `(resume c v)` runs it until it `(yield x)`s (resume returns x) or finishes (resume returns its result); `v` is the argument of `f` on the first resume and what `yield` returns on later ones · `(yield x)` outside a coroutine throws · `(alive c)` false once it has finished · `(drain c)` all its yielded values in a list · `(coclose c)` throws away a coroutine that is not running (its stack is reused; nothing in it is unwound). An error that is not caught inside the coroutine ends it and is thrown again by the `resume`, with its kind and data. Resuming a finished or running coroutine throws. A coroutine can resume another one. Each has 8 MB of machine stack and 8 MB of value stack (address space only; pages are used as they are touched), so tens of thousands can be alive at once; one that is never finished and never closed keeps its stack until the program ends.
```
walk t = (? t (: walk(t[0]) (yield t[1]) walk(t[2])))      ; in-order walk of [left value right] trees
(p (drain (co ()=>walk(tree))))
```
`lib/async.aklang` builds cooperative tasks on top: `(use "lib/async.aklang" as a)` · `(a.spawn f args..)` start a task · `(a.sleep ms)` · `a.pause()` let the others run · `(a.wait fd)` until fd is readable (accept, read, end of stream) · `a.chan()` `(a.send ch v)` `(a.recv ch)` (waits; nil once the channel is closed and empty) `(a.close ch)` · `a.run()` runs the tasks (poll(2) when all are waiting) until none is left that can progress; a task that throws prints `task error: msg` and ends. A server is then one task per connection of plain blocking-looking code (see `tests/native_only/async.aklang`: a server and 100 clients in one process). Zero-argument functions of a namespace are called `a.run()`; `(a.run)` is the function value.

## Windows and graphics (native only, Linux X11 / XWayland)
No libraries: `lib/x11.aklang` speaks the X11 protocol itself over the display's socket (`$DISPLAY`, cookie from `$XAUTHORITY` / `~/.Xauthority`), `lib/canvas.aklang` draws in software. `(use "../lib/x11.aklang")` includes both. Needs a depth-24 display; the window has a fixed size.
`cv=(canvas w h)` (BGRA pixels in `cv.px`) · `(fill cv c)` `(rect cv x y w h c a=255)` `(rrect cv x y w h r c)` `(circle cv cx cy r c a=255)` `(ring cv cx cy r thick c)` `(vgrad cv x y w h c1 c2)` anti-aliased; colours are `(rgb r g b)` numbers, `a` is opacity 0..255 · `(text cv x y "str" size c a=255)` → width (sizes 15 22 regular, 34 bold; ASCII; DejaVu, see `lib/FONT-LICENSE.txt`) `(text_w "str" size)` · `(blit dst dx dy src sx sy w h mask)` copy a region (mask: a canvas whose blue channel is the opacity, or nil) · `(copy_canvas dst src)` `(px cv x y)` `(save_ppm cv "f.ppm")`.
`w=(gui_open "title" width height)` · `(gui_present w cv)` shows a canvas (it is repainted by itself when uncovered) · `(gui_event w ms)` → the next event or nil after `ms` ms (no `ms`: sleep until one arrives, 0 CPU): `{:type "key" :key :down :shift :ctrl}` (keys are `"left" "enter" "esc" "tab" "backspace" "delete" "home" "end" "shift" "ctrl" "alt"` or the typed character) · `{:type "mouse" :button "left"|"middle"|"right" :down :x :y}` · `{:type "motion" :x :y}` (coalesced) · `{:type "wheel" :dy :x :y}` · `{:type "close"}` · `(gui_title w s)` `(gui_snapshot w)` → a canvas of what the window really shows · `(gui_close w)`. Under it: `(unixc path)` connects to a Unix socket, `(fdwn fd s off n)` writes part of a string/array. See `examples/connect4gui.aklang` (about 125 lines).

## JS target (`node boot/ak.js`, Node interop)
`(aw promise)` (async is inferred) · `(req "mod")` `(new C args)` `(js "raw js")` `imp ev delay` · Node built-in modules and JS globals are in scope: `fs.readFileSync(f)` `Math.max(1 2)` `path.basename(p)` · `node boot/ak.js f.aklang` also has `js` (print the generated JS), `build f.aklang out.js` (bundle) and `exe` (embeds node). None of these exist natively.

## Terminal (native only)
`(isatty)` stdin is a terminal · `(termsize)` → `[rows cols]` (nil if stdout is not a terminal) · `(rawmode f)` runs `(f)` with the terminal in raw mode (no echo, no line buffering, Ctrl-C is just a key) and always restores it, even if `f` throws · `(getkey ms)` → the next key as `"up" "down" "left" "right" "enter" "esc" "tab" "backspace" "ctrl-c" "eof"`, or the typed character (UTF-8 aware); nil when `ms` milliseconds pass without input (no `ms`: wait). Draw by writing ANSI escape sequences with `(fdw 1 s)` (one write per frame avoids flicker) — see `examples/connect4.aklang`.

## Cryptography (native)
`(use "lib/crypto.aklang" as c)` — primitives written in Ak, for `lib/tls.aklang`; byte data is a string in and out: `c.sha256 s` `c.sha384 s` · `c.hmac "sha256"|"sha384" key msg` · `c.hkdf_extract hash salt ikm` `c.hkdf_expand hash prk info n` · `c.chacha_seal key nonce aad plain` / `c.chacha_open key nonce aad data` (ChaCha20-Poly1305, 12-byte nonce, tag appended) · `c.aes_gcm_seal` / `c.aes_gcm_open` (same arguments; key of 16 or 32 bytes, 12-byte nonce) · `c.x25519 scalar point` `c.x25519_base scalar` · `c.random n` (getrandom) · `c.hex s` `c.unhex h`. The `open` functions return nil when the tag does not match (an empty plain text is `""`, so test with `nil`, not truthiness). Checked against Node's crypto on random inputs (`tests/crypto.test.js`). Not constant-time (arithmetic on BigInts and lists): fine for protocols over the network, not a defence against a local attacker timing the process.

## Certificates (native)
`(use "lib/pki.aklang" as k)` — X.509 and signatures in Ak: `k.pem_certs text` → DER strings · `k.cert_parse der` → map (`subject` `issuer` `nb` `na` `key` `san` `ips` `ca` `keyusage` `sigalg` `tbs` `sig`) · `k.verify_sig key alg data sig` (RSA PKCS#1 v1.5 and PSS, ECDSA P-256/P-384, SHA-256/384; `alg` is `rsa_pkcs1_sha256`, `rsa_pss_sha384`, `ecdsa_sha256`, ..) · `k.trust_roots()` loads the system bundle (`SSL_CERT_FILE` overrides; /etc/ssl/certs/ca-certificates.crt and the usual Red Hat/Alpine paths otherwise) · `k.check_chain ders host roots now` returns the parsed leaf or raises `certificate: why`. Checked: signatures along the chain up to a root, validity dates, CA flag and keyCertSign, subjectAltName match (wildcards for one label, IPv4 addresses; the CN is ignored). Not checked: revocation, name constraints, path length, extended key usage; SHA-1 and SHA-512 signatures are rejected. A signature check takes about 30 ms (RSA-2048), 90 ms (P-256) or 220 ms (P-384).

## TLS (native)
`(use "lib/tls.aklang" as t)` — a TLS 1.3 client in Ak (needs `crypto.aklang` and `pki.aklang`, loaded by it): `cn=(t.connect host port opts)` connects (like `tcpc`, so names are resolved with DNS), handshakes, verifies the certificate chain against the system CA bundle (`opts.roots`: your own parsed CA list; `opts.ms`: connect timeout) and the host name, and raises `tls: ...` on any failure; there is no way to turn verification off. `(t.read cn n=16384)` → up to n bytes, `""` at the end (`cn.truncated` is true if the peer hung up without close_notify) · `(t.write cn s)` · `(t.close cn)` · `(t.fd cn)` for `fdwait`. Supported: x25519, TLS_AES_128_GCM_SHA256, TLS_AES_256_GCM_SHA384, TLS_CHACHA20_POLY1305_SHA256, RSA-PSS and ECDSA (P-256/P-384) server signatures, KeyUpdate; ignored: session tickets. Not supported: TLS 1.2 and older, client certificates, resumption, 0-RTT, ALPN, HelloRetryRequest, other key exchange groups, a server side. A handshake takes about 0.2 s. Tested against Node's TLS server (all suites, EC and RSA certificates, 70 KB transfers) and OpenSSL s_server (KeyUpdate); not yet against public servers.

## Strings across targets
A native string is UTF-8 bytes; a JS string is UTF-16 units. For ASCII text the two are identical. The contract for other text:
- Same on both: `==` `++` `+` `split`/`join`/`starts`/`ends`/`has`/`rep` with a non-empty separator, `trim`, `rpt`, `show`, `json`/`unjson` (including `\u` escapes and surrogate pairs), `chr` and `ord` (code points; `ord` of a string reads its first character), regex with a literal pattern, and `idx` of a character that comes before any non-ASCII text.
- Counts units, so differs: `#s`, `s[i]`, `s[a..b]`, `take` `drop` `fst` `lst`, `for` over a string, `split s ""`, `idx` after non-ASCII text, `padl` `padr` and `fmt` widths. `(#"é")` is 2 natively and 1 on JS, `(#"😀")` is 4 and 2. A native slice may cut inside a character and give invalid UTF-8.
- Regex: `.` and classes match one code point natively; on JS only with the `u` flag: `(match (re "^.$" "u") s)`.
- `up` and `lo` map ASCII, Latin-1, Latin Extended-A, Greek and Cyrillic letters one to one natively; JS also applies special casing (`ß` -> `SS`, a final sigma), which natively stays as it is.
- Sizes: a count or length above 2^31 (lists and ranges: 2^27, `json` indent: 100) raises `invalid length: n` (`rpt`, `padl`, `padr`, `a..b step`, `json`, `fdr`, `udpfrom`) instead of hanging; `(exit x)` takes nil or an integer.
Portable code treats text as opaque (compare, join, split on ASCII separators) and uses `ord`/`chr` for characters. `tests/strings.test.js` runs one table of cases on both targets, so a change in either direction fails until this section is updated.
